## ✨ چرا یادداشتی؟

- **کاملاً آفلاین:** هیچ سروری، هیچ حسابی و هیچ ردیابی‌ای وجود ندارد؛ داده‌ها فقط در دیتابیس Room روی گوشی شما می‌مانند.
- **فارسی و راست‌به‌چپ:** کل رابط کاربری فارسی است و چیدمان از ابتدا RTL طراحی شده.
- **سریع و سبک:** Jetpack Compose + Room، بدون کتابخانه‌های سنگین و بدون تبلیغات.
- **حالت روشن و تیره:** با تمِ کاغذی گرم و تمِ شبانهٔ آرام، همراه با رنگ‌های ملایم برای هر یادداشت.

## 🧱 معماری

```
app/
├── MainActivity.kt              # میزبان Compose و ناوبری
├── data/
│   ├── Note.kt                  # موجودیت Room + DAO + دیتابیس + NoteRepository
│   └── AppContainer.kt          # کانتینر وابستگی + DataStore تنظیمات
└── ui/
    ├── NotesViewModel.kt        # StateFlow ها و عملیات
    ├── Format.kt                # تاریخ/عدد فارسی
    ├── theme/Theme.kt           # رنگ‌ها و تایپوگرافی
    └── screens/                 # فهرست، ویرایشگر، تنظیمات
```

شرح کامل لایه‌ها، مدل داده و تصمیم‌های طراحی در [ARCHITECTURE.md](ARCHITECTURE.md) آمده است. اپلیکیشن از الگوی **MVVM + Repository** استفاده می‌کند: UI (Compose) ← ViewModel (StateFlow) ← Repository ← Room/DataStore.

## 🛠 ساخت از سورس

```bash
# پیش‌نیاز: JDK 17 و Android SDK 35
gradle :app:assembleDebug
# خروجی: app/build/outputs/apk/debug/app-debug.apk
```

بیلد خودکار روی GitHub Actions انجام می‌شود و APK را در Releases و پوشهٔ [`releases/`](releases/) می‌گذارد.

## 🔐 حریم خصوصی

یادداشتی هیچ داده‌ای جمع‌آوری نمی‌کند، به اینترنت نیاز ندارد و مجوز خاصی از اندروید درخواست نمی‌کند. پشتیبان‌گیری فقط با انتخاب خود شما و از طریق اشتراک‌گذاری فایل انجام می‌شود.

## 🩺 رفع اشکال‌های نسخهٔ ۱

پیش از انتشار، سورس برنامه بازبینی شد و این باگ‌ها برطرف شدند (ظاهر برنامه دست نخورده است):

- **رفع خطای اجرا (Crash):** کلاس `Application` در `AndroidManifest` با مسیر اشتباه ثبت شده بود (`‎.YaddashtyApp` در حالی که کلاس در بستهٔ `data` است). این مورد باعث بسته‌شدن فوری برنامه روی بعضی دستگاه‌ها می‌شد.
- **زنده‌شدن فهرست یادداشت‌ها:** صفحهٔ فهرست، `StateFlow` ها را جمع (collect) نمی‌کرد و فقط یک عکس لحظه‌ای از دیتابیس نشان می‌داد؛ بعد از ساخت یا ویرایش یادداشت، فهرست تا تعامل بعدی به‌روز نمی‌شد.
- **مسابقهٔ ذخیره و بایگانی:** بایگانی/حذف هم‌زمان با ذخیرهٔ خودکار انجام می‌شد و می‌توانست ذخیره‌سازی را خنثی کند؛ حالا هر دو در یک نوشتن اتمیک روی دیتابیس انجام می‌شوند.
- **یادداشت خالی:** اگر یادداشت تازه بدون هیچ متنی بسته می‌شد، یک ردیف خالی در دفترچه باقی می‌ماند؛ اکنون پیش‌نویس دست‌نخورده پاک می‌شود.
- **پشتیبان JSON:** خروجی به‌جای رشتهٔ دست‌ساز با `JSONObject` ساخته می‌شود (کاراکترهای کنترلی هم درست escape می‌شوند) و به‌صورت فایل واقعی با `FileProvider` به اشتراک گذاشته می‌شود.
- **تکثیر یادداشت:** نسخهٔ کپی دیگر وضعیت بایگانی/سطل زبالهٔ اصل را به ارث نمی‌برد.
- **پایداری تنظیمات:** خواندن DataStore در برابر خطا محافظت شد تا انتخاب تم برنامه را از کار نیندازد.

> شناخته‌شده و بدون تغییر در نسخهٔ ۱: بازیابی پشتیبان (Import) هنوز در رابط کاربری وجود ندارد؛ فقط خروجی JSON پشتیبانی می‌شود. این مورد در نسخه‌های بعدی اضافه خواهد شد.

### بازبینی دوم (همان نسخهٔ ۱)

- **جلوگیری از پاک‌شدن محتوا:** اگر بلافاصله پس از باز شدن یادداشت، دکمهٔ سنجاق/بایگانی/حذف زده می‌شد، فیلدهای هنوز بارگذاری‌نشده (خالی) روی یادداشت نوشته می‌شدند؛ حالا این عملیات تا آماده‌شدن ویرایشگر غیرفعال است.
- **جستجوی فارسی واقعی:** «ي/ك» عربی، نیم‌فاصله، اعراب و ارقام فارسی/عربی هنگام جستجو یکسان‌سازی می‌شوند؛ قبلاً جستجوی «یادداشت» با «يادداشت» نتیجه نمی‌داد.
- **تاریخ شمسی:** تاریخ کارت‌ها به‌جای میلادی (با ارقام فارسی) حالا شمسی نمایش داده می‌شود.
- **ذخیرهٔ مطمئن‌تر:** در صورت خروج ناگهانی از ویرایشگر، پیش‌نویس در انتظار ذخیرهٔ خودکار همان لحظه ذخیره می‌شود.
